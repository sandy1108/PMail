# 收件别名

在“设置 → 邮箱别名”中填写地址前缀、选择托管域名，可添加备注。创建后默认启用，发往别名的邮件进入当前账号邮箱。每个用户可自行管理自己的别名，不设累计数量配额；列表分页加载。

别名只用于收件，没有密码，不能登录，也不能作为发件身份。发送邮件和登录仍使用真实账号。未登记、已停用、已删除或所属用户被禁用的地址拒收，不转交管理员。加号不是自动子地址：例如 `shopping+news@example.com` 必须完整登记才能收件。

同一SMTP事务中，主地址和多个别名指向同一用户时只投递一份；不同用户各获得自己的邮件关联。邮件详情的“实际投递地址”仅显示当前用户命中的信封地址，原始邮件头保持原样。旧邮件没有这项历史信息，不根据现存别名补猜。

## 管理和地址规则

- 可复制地址、编辑备注、停用、恢复或删除。地址和归属不能直接修改。
- 停用仍保留名称；删除释放名称，可能被其他用户重新登记。长期对外使用的地址建议停用保留。两种操作均保留已收邮件。
- 前缀去除首尾空白并转小写，支持ASCII字母、数字、下划线、连字符、加号和点，长度1–64字节；点不能在首尾或连续出现。
- 域名只能来自服务端配置的 `domain` / `domains`；完整地址最长254字节。
- 别名按完整地址唯一，同名前缀在不同托管域名可分别登记。
- 真实账号在所有托管域名有效，因此其前缀不能被任何别名使用，禁用真实账号仍占名。反之，新真实账号不能使用任何已有别名的前缀，停用别名也占名。
- 备注最多200个Unicode字符。搜索匹配地址或备注。

## HTTP接口

以下接口均为POST JSON，沿用项目响应格式 `errorNo` / `errorMsg` / `data`。必须使用有效网页登录会话，并通过既有同源JSON及CSRF检查；只读Bearer授权码不能调用。请求体上限4096字节，未知字段拒绝。用户归属由服务端认证上下文确定，不接受 `user_id`。

| 路径 | 请求字段 | 成功data |
|---|---|---|
| `/api/settings/aliases/create` | `local_part`, `domain`, 可选 `remark` | 新别名对象 |
| `/api/settings/aliases/list` | 可选 `current_page`, `page_size`, `keyword` | `list`, `total`, `current_page`, `page_size` |
| `/api/settings/aliases/update` | `id`, `remark`, `enabled`，三个均需提供 | `true` |
| `/api/settings/aliases/delete` | `id` | `true` |

`list` 默认第一页、每页20条；每页1–100条，页码最多1000000，关键词最多200字节。这个每页上限不是别名数量配额。别名对象包含 `id`, `local_part`, `domain`, `address`, `remark`, `enabled`, `created_at`, `updated_at`，不返回所属用户ID。

更新只改备注和启用状态。无论是否管理员，均只能操作自己的别名；他人ID与不存在ID返回一致的不可用错误。业务错误包含非法参数、地址占用、别名不可用；数据库内部错误不直接返回。

## 投递一致性与运行边界

SMTP根据RCPT TO信封地址解析归属，不根据To/Cc邮件头决定接收用户。RCPT记录归属快照，DATA阶段在事务中复验；地址删除重建、停用或用户禁用导致归属变化时，返回临时失败，不错投或部分保存。数据库查询及持久化故障同样返回临时失败，便于发件服务器重试。未知地址在RCPT阶段永久拒收，其他已接受收件人仍可继续事务。

本地规则转发复用相同地址解析，并按最终用户ID阻止转给自己的别名形成循环。既有邮件规则仍依据原始内容匹配，本功能不新增信封地址规则条件。

地址占用与最终投递使用单进程互斥及数据库事务；别名完整地址另有唯一索引。**不支持多进程共享数据库并发管理地址**，这种部署需另行实现数据库级统一命名空间约束。

## 升级与回退

启动时通过现有Xorm同步新增 `email_alias` 表及 `user_email.delivery_addresses` 列，后者保存按用户区分的JSON信封地址列表。不迁移账号口令，不改授权码权限或协议开关。

上线前应核对历史账号大小写及前缀语义是否冲突，备份程序、配置和一致性数据库副本，并在副本验证增量升级。当前定向测试使用SQLite，未宣称其他数据库完成运行验证。

回退旧程序后，旧版不识别别名，别名将停止收件；应先在数据库副本验证旧程序兼容新增表列。保留升级后收到的邮件，不能用升级前数据库快照直接覆盖当前数据库。

本地构建和隔离测试不等于目标设备运行或外部邮件投递验收，部署后还需验证实际入口、日志及外部收件。
