# 开发与验证说明

## 空POST与浏览器请求

Axios将method规范化为小写；POST无data时，浏览器适配器会移除Content-Type。同源JSON校验因此可能返回403，前端响应拦截器继而跳转登录页。统一入口将undefined的POST数据补为{}，保留服务端Origin与JSON检查。`node scripts/test-empty-post.cjs`通过真实Axios浏览器适配器和伪XHR验证，不访问网络。

## 进程与端口检查

端口预检查使用SO_REUSEADDR，允许TIME_WAIT复用，同时拒绝实际监听占用者。不能通过强杀未知进程解决冲突。

macOS的ps输出可能截断命令，应使用`ps -ww`、将command列放最后，并结合启动时间核对PID身份。进程存在不代表HTTP或SMTP已经就绪，部署验收应另外检查实际监听与协议响应。

## 邮箱与网络边界

邮箱后缀`example.com`、服务主机`mail.example.com`及管理员权限是不同概念。管理员收件箱不会自动汇总其他用户邮件，排查时应核对收件人和user_email关联。

PROXY头位于SMTP内容之前，必须限制直接来源、版本和读取超时，再使用原始IP进行来源判断。入站代理不会改变外发网络出口。

## 数据与测试

SQLite运行时备份应使用backup API等一致性方式；回退程序前先保全当前邮件，不直接覆盖数据库。日志记录投递事件，避免记录口令、哈希、配置全文和邮件正文。

交叉编译、本地回归、目标平台运行和真实网络投递分别验证。构建成功不表示所有协议、UI、送达率和安全性已验收。上游集成测试依赖特定配置时，应明确运行范围和环境，避免外发副作用。
